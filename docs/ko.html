푸시하기 전에, 내 변경이 어디에 닿는지 확인하세요.

rintel은 저장소를 한 번 읽고, 텍스트 검색으로는 틀리기 쉬운 질문에 답합니다. 누가 이걸 호출하는지, 바꾸면 무엇이 깨지는지, 어떤 테스트가 덮고 있는지, 무엇이 위험한지. 로컬에서만 돌고, 읽는 코드를 실행하지 않습니다.

go install github.com/spro1/rintel-code/cmd/rintel@latest
cd your-repository
rintel report --open
보고서 직접 열어 보기 시작하기 GitHub 소스

무엇을 물어볼 수 있나

터미널, CI, 코딩 에이전트에서 씁니다. 추정이라고 표시되지 않은 답은 모두 정적 분석으로 확인한 사실입니다.

질문명령
누가 이걸 호출하나?rintel callers UserService.createUser
이 타입이나 필드는 어디서 쓰이나?rintel refs UserDto
내 변경이 어디에 영향을 주나? 어떤 테스트를 돌려야 하나?rintel impact --base origin/main
REST 엔드포인트는 뭐가 있고 무엇이 처리하나?rintel api
보안이나 구조에 문제가 있나?rintel check
의존성에 알려진 취약점이 있나?rintel check --vulns
복잡한 곳은 어디인가?rintel metrics method --top 20
패키지들은 서로 어떻게 의존하나?rintel deps

무엇이 다른가

로컬에서만 돌고, 아무것도 실행하지 않습니다

소스는 PC 밖으로 나가지 않고, 저장소의 빌드 도구·어노테이션 프로세서·패키지 스크립트를 실행하지 않고, 심볼릭 링크를 따라가지 않습니다. 신뢰할 수 없는 코드에 돌릴 수 있도록 만들었습니다.

모든 답에 근거가 붙습니다

사실에는 표시가 없습니다. 추정에는 사용한 규칙 이름이 붙습니다. 분석이 보지 못한 곳은 사유와 함께 기록하므로 "없음"과 "못 봄"을 혼동하지 않습니다.

발견 항목마다 수정 방법이 있습니다

보안·품질 규칙 22개. 해당하는 CWE 번호와 무엇을 바꿔야 하는지를 함께 알려 줍니다.

인덱스 하나, 쓰는 방법 셋

명령어, 코딩 에이전트용 MCP 서버와 스킬, 오프라인에서 열리는 HTML 보고서 한 장.

코딩 에이전트에서

Claude Code 플러그인이 스킬 세 개와 MCP 서버를 추가합니다. 에이전트가 grep으로 추측하지 않고 실제 호출 관계를 확인합니다.

/plugin install rintel --marketplace spro1/rintel-code
  • rintel: 누가 호출하나, 어디서 쓰이나, 지워도 되나
  • /rintel:impact: 변경이 미치는 범위와 돌릴 테스트
  • /rintel:security: 발견 항목을 코드와 대조해 판정하는 보안 검토
  • MCP를 지원하는 다른 에이전트도 쓸 수 있습니다: rintel mcp

가이드

  • 시작하기: 설치, 첫 스캔, 첫 답
  • 변경 검토: 영향 범위, 돌릴 테스트, 안전한 삭제
  • CI에서 쓰기: 품질·보안 게이트, SARIF
  • Claude Code에서 쓰기: 플러그인, 스킬, MCP 서버

지원 언어

Java(Spring, Lombok), Go, TypeScript·JavaScript(React, Vue), Python. 각 언어를 그 언어의 도구로 해석합니다: JDK, Go 툴체인, Node.js와 내장 TypeScript 컴파일러, python3.

Apache-2.0. 데모 보고서는 spring-petclinic(Apache-2.0)을 분석한 것으로, 심볼 이름과 파일 경로만 담고 소스 코드는 없습니다.
